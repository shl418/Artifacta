# 修复执行计划 — 2026-06-06

依据 `docs/reports/2026-06-06-deep-code-review.md` 的 P0–P2 清单，分阶段落地。
每阶段独立提交并跑 `typecheck`/`lint`/相关测试；全部完成后整体 `build` + `smoke`。

## 原则
- 变更操作与管理员读取强制 API Key scope；允许匿名 public 访问的资源 GET 保持裸认证，
  其安全问题用序列化脱敏解决（避免误伤匿名访问）。
- 架构级大改（如 Postgres 多实例原子写）采用「正确的轻量修复 + 明确文档声明」，不做超范围重写。
- 不破坏现有测试与 smoke；新增行为补单元测试。
